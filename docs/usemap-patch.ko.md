# 임진록2+ 유즈맵 패치

임진록2+ 조선의반격의 실행파일을 고쳐 일반 게임을 시작할 때 맵에 배치된 유닛이 나오게 한다. 플레이어마다 시작 유닛을 만드는 호출 여섯 개를 지우고 그 함수가 끝나는 자리에서는 게임 내 코드로 건너뛰게 했다. 맵의 유닛 배치 표를 돌며 유닛을 만드는 코드다.


## 대상

| 항목 | 값 |
|---|---|
| 게임 | 임진록2+ 조선의반격 v1.1000 (+ HQ Net 패치) |
| 파일 | `syw2plus.exe` (1,032,192바이트) |
| md5 | `ec9f2843de992af91c575bab2e9b64fe` |

패킹은 없고 이미지 베이스는 `0x400000` 이다. 고친 곳은 전부 `.text` 섹션 안이고, `.text` 는 가상 주소 `0x401000` 이 파일 오프셋 `0x1000` 에 놓여 있다. 그래서 **파일 오프셋 = 가상 주소 - 0x400000** 이다.


## 바꾼 바이트

| 가상 주소 | 파일 오프셋 | 원래 바이트 | 바꾼 바이트 | 의미 |
|---|---|---|---|---|
| `0x0041F18F` | `0x1F18F` | `E8 FC 3F 02 00` | `90 90 90 90 90` | 시작 유닛 생성 호출을 지운다 |
| `0x0041F1CF` | `0x1F1CF` | `E8 BC 3F 02 00` | `90 90 90 90 90` | 시작 유닛 생성 호출을 지운다 |
| `0x0041F251` | `0x1F251` | `E8 3A 3F 02 00` | `90 90 90 90 90` | 시작 유닛 생성 호출을 지운다 |
| `0x0041F293` | `0x1F293` | `E8 F8 3E 02 00` | `90 90 90 90 90` | 시작 유닛 생성 호출을 지운다 |
| `0x0041F2E6` | `0x1F2E6` | `E8 A5 3E 02 00` | `90 90 90 90 90` | 시작 유닛 생성 호출을 지운다 |
| `0x0041F328` | `0x1F328` | `E8 63 3E 02 00` | `90 90 90 90 90` | 시작 유닛 생성 호출을 지운다 |
| `0x0041F356` | `0x1F356` | `C3 90 90 90 90 90` | `E9 A0 4B 0A 00 C3` | `ret` 대신 맵 유닛 배치 루프로 점프 |
| `0x004C3F73` | `0xC3F73` | `B9 70 67 95 00` | `E9 E3 B3 F5 FF` | 루프가 끝나면 `0x0041F35B` 의 `ret` 으로 돌아온다 |


## 시작 유닛을 만드는 함수

`0x0041F0E0` 은 게임 방식으로 보이는 값 `[0x00975914]` 가 3 이면 `0x0041F360` 을 부르고 끝난다. 3 이 아니면 `0x0041F0F8` 로 내려가 플레이어 여덟 명의 시작 유닛을 만든다.

```
0041F0E0  66 83 3D 14 59 97 00 03  cmp  word [0x00975914], 3
0041F0E8  75 0E                    jnz  0x0041F0F8
0041F0EA  8B 44 24 04              mov  eax, [esp+4]
0041F0EE  50                       push eax
0041F0EF  E8 6C 02 00 00           call 0x0041F360
0041F0F4  83 C4 04                 add  esp, 4
0041F0F7  C3                       ret
0041F0F8  53 55 8B 6C 24 0C 56 57  push ebx ; push ebp ; mov ebp, [esp+0xC] ; push esi ; push edi
0041F100  33 F6 33 FF              xor  esi, esi ; xor edi, edi
0041F104  BB 70 67 95 00           mov  ebx, 0x00956770    ; 플레이어 1 정보
```

플레이어 정보는 `0x00956770` 부터 `0x3ABC` 바이트 간격으로 여덟 개가 있고 첫 바이트가 종족이다. 종족이 1, 2, 3 일 때 각각 유닛 종류 두 개를 만들고, `[0x00975914]` 가 1 이면 종류 `0x51` 하나를 더 만든다. 위치는 `0x00B3DE58 + 플레이어 번호 * 0x338` 의 x, `0x00B3DE5C + 플레이어 번호 * 0x338` 의 y 다.

| 호출 위치 | 유닛 종류 | 조건 |
|---|---|---|
| `0x0041F18F` | `0x51` | `[0x00975914]` 가 1 |
| `0x0041F1CF` | `0x31` | 종족 1 |
| `0x0041F293` | `0x07` / `0x1F` | 종족 1 / 종족 2 (두 갈래가 같은 호출을 쓴다) |
| `0x0041F251` | `0x3A` | 종족 2 |
| `0x0041F2E6` | `0x46` | 종족 3 |
| `0x0041F328` | `0x15` | 종족 3 |

호출 하나는 이런 모양이다. `0x00442FA0(종류)` 가 0 이 아닌 값을 돌려주면 그 값과 함께 `0x00443190` 을 부른다.

```
0041F21F  6A 3A                 push 0x3A
0041F221  E8 7A 3D 02 00        call 0x00442FA0
0041F226  0F BF C8              movsx ecx, ax
0041F229  83 C4 04              add  esp, 4
0041F22C  85 C9                 test ecx, ecx
0041F22E  74 29                 jz   0x0041F259
0041F230  0F BF C6              movsx eax, si
0041F233  69 C0 38 03 00 00     imul eax, eax, 0x338
0041F239  57                    push edi               ; 플레이어 번호
0041F23A  6A 64                 push 100
0041F23C  66 8B 90 5C DE B3 00  mov  dx, [eax+0x00B3DE5C]  ; y
0041F243  66 8B 80 58 DE B3 00  mov  ax, [eax+0x00B3DE58]  ; x
0041F24A  6A 01                 push 1
0041F24C  52                    push edx
0041F24D  50                    push eax
0041F24E  51                    push ecx
0041F24F  6A 3A                 push 0x3A              ; 유닛 종류
0041F251  E8 3A 3F 02 00        call 0x00443190        ; 패치에서 NOP 다섯 개
0041F256  83 C4 1C              add  esp, 0x1C
```

`0x00443190` 은 cdecl 이다. 인자 정리(`add esp, 0x1C`)를 호출한 쪽이 하니 `CALL` 만 `NOP` 으로 지워도 스택이 그대로 맞는다.

함수 끝은 레지스터를 되돌린 뒤 `ret` 이다. 이 `ret` 자리를 맵 유닛 배치 루프로 가는 `JMP` 로 바꿨다. 뒤의 `90` 다섯 개 중 마지막 자리에 `ret` 을 새로 두어 돌아올 곳으로 썼다.

```
0041F352  5F 5E 5D 5B           pop edi ; pop esi ; pop ebp ; pop ebx
0041F356  C3                    ret                    ; 원본
0041F356  E9 A0 4B 0A 00        jmp  0x004C3EFB        ; 패치
0041F35B  C3                    ret                    ; 패치 (원래 90)
```


## 맵 유닛 배치 루프

`0x004C3E50` 함수 안에 맵의 유닛 배치 표를 돌며 유닛을 만드는 루프가 있다. 표는 `0x00B3F818` 부터 16바이트 항목 800개다.

| 항목 안 위치 | 크기 | 내용 |
|---|---|---|
| `+0x0` | 4 | 유닛 종류 (0 과 1 은 건너뛴다) |
| `+0x4` | 2 | x |
| `+0x8` | 2 | y |
| `+0xC` | 2 | 소유 플레이어 |

```
004C3EF9  33 FF                 xor  edi, edi
004C3EFB  BE 20 F8 B3 00        mov  esi, 0x00B3F820   ; 패치의 점프가 들어오는 곳
004C3F00  8B 46 F8              mov  eax, [esi-8]      ; 유닛 종류
004C3F03  83 E8 00              sub  eax, 0
004C3F06  74 60                 jz   0x004C3F68
004C3F08  48                    dec  eax
004C3F09  74 5D                 jz   0x004C3F68
004C3F0B  66 8B 46 FC           mov  ax, [esi-4]       ; x
004C3F0F  66 8B 0E              mov  cx, [esi]         ; y
004C3F12  66 85 C0              test ax, ax
004C3F15  7C 51                 jl   0x004C3F68
004C3F17  66 3B 05 34 DE B3 00  cmp  ax, [0x00B3DE34]
004C3F1E  7D 48                 jge  0x004C3F68
004C3F20  66 85 C9              test cx, cx
004C3F23  7C 43                 jl   0x004C3F68
004C3F25  66 3B 0D 36 DE B3 00  cmp  cx, [0x00B3DE36]
004C3F2C  7D 3A                 jge  0x004C3F68
004C3F2E  66 8B 56 04           mov  dx, [esi+4]       ; 소유 플레이어
004C3F32  52                    push edx
004C3F33  6A 64                 push 100
004C3F35  6A 01                 push 1
004C3F37  51                    push ecx
004C3F38  50                    push eax
004C3F39  66 8B 46 F8           mov  ax, [esi-8]
004C3F3D  57                    push edi
004C3F3E  50                    push eax
004C3F3F  E8 4C F2 F7 FF        call 0x00443190        ; 시작 유닛과 같은 생성 함수
004C3F44  83 C4 1C              add  esp, 0x1C
...
004C3F68  47                    inc  edi
004C3F69  83 C6 10              add  esi, 0x10
004C3F6C  66 81 FF 20 03        cmp  di, 800
004C3F71  7C 8D                 jl   0x004C3F00
004C3F73  B9 70 67 95 00        mov  ecx, 0x00956770   ; 원본
004C3F73  E9 E3 B3 F5 FF        jmp  0x0041F35B        ; 패치
```

루프가 끝난 자리(`0x004C3F73`)를 `0x0041F35B` 의 `ret` 으로 가는 점프로 바꿨으니 시작 유닛 함수는 맵에 배치된 유닛을 만든 뒤 원래 호출한 곳으로 돌아간다.


## 추가 확인 대상

- 점프가 들어오는 `0x004C3EFB` 는 `xor edi, edi` 다음 명령이다. 루프 번호 `edi` 는 호출한 쪽의 `edi` 값, 곧 `0x0041F352` 에서 되돌린 값에서 시작한다.
- `0x004C3E50` 함수도 같은 루프를 지나므로 패치 후에는 루프 뒤에서 `0x0041F35B` 로 간다. 이 함수를 부르는 `0x00424D30` 이 어느 화면의 경로인지.
- `[0x00975914]` 의 각 값이 어느 게임 방식인지, 표를 채우는 코드가 어디인지.


## 직접 패치하기

1. `syw2plus.exe` 의 md5 가 `ec9f2843de992af91c575bab2e9b64fe` 인지 확인한다.
2. 헥스 에디터로 위 표의 파일 오프셋으로 가서 원래 바이트가 맞는지 본다.
3. 바꾼 바이트로 덮어쓴다. 길이는 원래 바이트와 같다.
